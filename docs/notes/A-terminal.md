## Section transversale : `llama-server` b10216 et le tool-calling

Sources : [tools/server/README.md @b10216](https://github.com/ggml-org/llama.cpp/blob/b10216/tools/server/README.md), [docs/function-calling.md @b10216](https://github.com/ggml-org/llama.cpp/blob/b10216/docs/function-calling.md).

- `--jinja` est « default: enabled » dans le README du serveur de ce tag (l.225) : le flag explicite n'est plus nécessaire pour activer le tool-calling OpenAI, mais le passer reste inoffensif.
- `function-calling.md` : le tool-calling OpenAI est pris en charge avec `--jinja` ; le format natif de **Qwen 2.5 Coder** est géré ; un gestionnaire « Generic » est utilisé quand le gabarit de chat n'est pas reconnu.

- La couverture, côté `/v1/responses`, des outils `custom`/freeform (utilisés par `apply_patch` de Codex) n'est pas documentée → **non vérifié**.
- Conséquence par outil (voir sections) : appels natifs `tool_calls` pour OpenCode, Goose, Crush, Qwen Code, Pi ; formats texte sans tool-calling pour Aider ; repli XML pour Qwen Code et Plandex ; Codex n'utilise plus que l'API Responses ; mini-swe-agent v2 utilise le tool-calling natif avec un mode texte de repli.
